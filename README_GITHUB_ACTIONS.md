# Hut Availability Bot — версія для GitHub Actions

Бот перевіряє наявність вільних місць на двох сайтах бронювання
(Pięć Stawów, Murowaniec) і шле повідомлення в Telegram, коли з'являються
нові дати. Працює повністю в хмарі GitHub — комп'ютер вмикати не треба.

## Файли

- `check_once.py` — робить одну перевірку і завершується (для локального
  постійного бота дивись окремо `monitor.py`, він тут не потрібен).
- `.github/workflows/check.yml` — розклад (cron), який запускає
  `check_once.py` кожні 15 хвилин.
- `state.json` — з'явиться сам після першого запуску, зберігає, які дати
  вже були відомі, щоб не дублювати сповіщення.

## Налаштування (5-10 хв)

### 1. Створи Telegram-бота
- Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → отримаєш токен.
- Дізнайся свій `chat_id` через [@userinfobot](https://t.me/userinfobot)
  (напиши йому будь-що, він покаже твій id).

### 2. Створи репозиторій на GitHub
- Зроби новий **приватний** репозиторій (приватний — щоб токен/URL не світились
  публічно, хоча токен все одно піде через Secrets, а не в код).
- Заливи туди файли `check_once.py` і `.github/workflows/check.yml`
  (структуру папок зберігай — `.github/workflows/` має бути саме так).

### 3. Додай секрети
У репозиторії: **Settings → Secrets and variables → Actions → New repository secret**
- `TELEGRAM_BOT_TOKEN` — токен бота
- `TELEGRAM_CHAT_ID` — твій chat_id

### 4. Увімкни Actions
- Вкладка **Actions** у репозиторії → якщо попросить підтвердити — підтверди,
  що хочеш увімкнути workflows.
- Перший запуск можна зробити вручну: Actions → "Check hut availability" →
  **Run workflow**.

## !! Обов'язково перед запуском !!

Так само, як і в попередній версії — селектори в `TARGETS` всередині
`check_once.py` (`day_selector`, `unavailable_class`, атрибут дати) — це
заглушки. Відкрий сайт бронювання в браузері, DevTools (F12) → Elements,
подивись реальну розмітку днів у календарі й онови значення.

**Порада:** якщо в DevTools → Network знайдеш прямий JSON-запит з даними
про доступність (дуже ймовірно, що є) — краще переписати `check_once.py`
на прямі `httpx`-запити без Playwright взагалі. Це:
- зробить перевірку набагато швидшою (секунди замість ~10-20 с),
- зніме потребу ставити Chromium (`playwright install --with-deps chromium`
  займає найбільше часу в workflow),
- дозволить, за бажання, перевіряти частіше за 15 хв.

## Обмеження безкоштовного GitHub Actions

- Безкоштовний ліміт — 2000 хвилин/міс для приватних репо (для публічних —
  необмежено). Одна перевірка з Playwright займає орієнтовно 1-2 хв
  (включно з встановленням Chromium), тобто раз на 15 хв — це приблизно
  100-200 хв/день... що вже за місяць може вийти за безкоштовний ліміт.
  **Тому раджу або зробити репозиторій публічним, або перейти на прямий
  API-запит (без браузера) — тоді ліміт не буде проблемою.**
- `schedule`-тригер у GitHub Actions не гарантує точний час запуску — може
  бути затримка на кілька хвилин у пікові періоди. Для цієї задачі це не
  критично.

## Локальна альтернатива

Якщо захочеш замість цього тримати бота на власному сервері (VPS) з
безкінечним циклом (без обмежень по хвилинах, точніший інтервал) —
є версія `monitor.py`, яку я давав раніше: та сама логіка, але крутиться
постійно як окремий процес.
